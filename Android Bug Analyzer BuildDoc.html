1. 项目概述

1. Project Overview

Android Bug Analyzer 是一款专为 Android Studio 开发的插件，旨在解决移动开发者在分析大型 Bug Report 日志文件时遇到的性能和工具碎片化问题。它通过自定义的高性能文件读取算法和集成化的搜索工具，提供了一站式的日志分析体验。

Android Bug Analyzer is an Android Studio plugin built to solve performance bottlenecks and tooling fragmentation when analyzing large Bug Report log files. It offers a unified analysis experience via a custom high-performance file reading algorithm and integrated search tools.

2. Code Structure & Implementation Details

SearchEngine.java

用途： 提供高性能、低内存占用的文件搜索服务。

Purpose: Provides high-performance, low-memory file searching services.

核心算法 (searchFile):

Core Algorithm (searchFile):

  • 流式读取： 使用 BufferedReader 逐行读取文件，避免将整个文件加载到 RAM 中，从而支持只有几百 MB 内存分配的 IDE 处理 GB 级日志。
  • 正则编译优化： 如果启用了正则搜索，Pattern 对象在循环外预编译一次，避免重复编译开销。
  • 双重过滤逻辑：
    • 查询 (Query)： 首先检查行是否包含 Search Text 或匹配 Regex 模式。
    • 关键字 (Keywords)： 接着应用关键字过滤器。算法根据 matchAllKeywords 标志动态切换逻辑：
      true (AND): 遍历所有关键字，如果行缺少任意一个关键字，则丢弃。
      false (OR): 遍历所有关键字，如果行包含任意一个关键字，则保留并终止检查。
KeywordManager.java

用途： 管理用户定义的关键字配置及持久化。

Purpose: Manages configuration and persistence of user-defined keywords.

实现逻辑： 使用 Jackson 库将关键字及其分类存储为 JSON 格式 (keywords.json)。提供了增删改查 API，并负责处理旧版本 TXT 配置文件的迁移。数据结构为 Map<String, List<String>> 实现分类管理。

Logic: Uses Jackson to serialize keywords/categories to JSON (keywords.json). Provides CRUD APIs and handles legacy TXT migration. Data is structured as Map<String, List<String>>.

FileMetadata.java

用途： 描述单个被分析文件的属性。

Purpose: Describes attributes of a single analyzed file.

逻辑： 除了基础的文件名和路径，核心字段 splitParts 是一个字符串列表。当日志文件过大时，工具会自动将其拆分，此字段记录拆分后的子文件名序列，以便 UI 层能够将被拆分的文件呈现为一个逻辑整体。

Logic: Key field splitParts (List<String>) tracks split segments of large files, allowing the UI to present them as a single logical entity despite physical segmentation.

TextPanel.java

用途： 核心日志阅读器，实现高性能分页显示。

Purpose: Core log viewer implementing high-performance pagination.

核心算法 (Pagination & Rendering):

Core Algorithms:

  • 分页加载 (loadFile/loadPage): 利用 Java NIO 的 Files.lines() 流。通过 stream.skip(offset).limit(limit) 方法只读取当前页所需的行数。这避免了加载整个文件，瞬间响应翻页操作。默认页大小为 2000 行。
  • 自定义渲染 (HighlightRenderer): 扩展 JTextArea 实现 ListCellRenderer。在 getListCellRendererComponent 中，根据当前行的索引检查是否在 searchResults 列表中，如果是，则设置背景色为高亮黄，实现搜索结果的视觉反馈。
  • 原地编辑 (In-Place Editor): Swing 的 JList 不支持直接文本选择。本类通过计算单元格的屏幕坐标 (getCellBounds)，在 JLayeredPane 的顶层动态叠加一个透明的 JTextArea，模拟出“双击选中复制”的交互效果。
SearchResultDialog.java

用途： 执行全局搜索并展示聚合结果。

Purpose: Executes global search and displays aggregated results.

技术细节：

  • 多线程架构： 搜索任务在独立的 Thread 中运行。该线程周期性检查 isCancelled 标志或 Thread.interrupted() 状态，确保用户关闭对话框时搜索能立即停止，防止后台资源泄露。
  • 参数传递： 将过滤面板中选定的 keywords 列表和 matchAll (AND/OR) 状态直接传递给 SearchEngine，实现界面与逻辑的解耦。
KeywordFilterPopup.java

用途： 悬浮式关键字过滤配置面板。

Purpose: Floating panel for keyword filter configuration.

逻辑： 动态生成复选框列表。包含一个关键的 "Match All (AND)" 复选框，该控件的状态直接决定了全工程搜索的逻辑过滤模式。
